## 为什么标签页文案值得单独一改

P2 时插件注册里是 `label: () => en['view.theater']`——能跑，但违反 0.1.2 的硬规则：**所有产品文案归 locale 字典所有**。中文用户会看到一个英文标签。

改法是在类型镜像里补上 `ctx.locale.translate`，注册时用它：

```ts
label: () => ctx.locale.translate(NS, 'view.theater'),
```

有测试守着，防止以后回退成硬编码：

```ts
it('takes the tab label from the locale service, not a hardcoded string', () => {
  expect(registrations[0]?.label()).toBe('t:view.theater')   // 假 ctx 返回 t:<key>
})
```

## 字典完备性测试：三条不变量

字典对等这件事，人工检查一定会漏。三个测试机械化守住：

| 测试 | 防什么 |
|---|---|
| 键集合完全相同 | 一种语言少一个键 → 该语言显示 key 字符串 |
| 无空值 | 占位式空串混进发布 |
| **占位符集合对齐** | `{count}` 在英文有、中文漏 → 中文永远显示不出数字 |

第三条最容易被忽略，也最难靠肉眼发现——它逐键比对两种语言的 `{placeholder}` 集合。

## 插件注册契约测试：防三类静默失败

一个插件挂错了不会报错，只是**什么都不显示**。所以用假 ctx 断言注册行为：

- 声明的服务依赖正确（`['slots', 'locale', 'sessions']`）
- 注册到 `conversation.view` 且 id 为 `replay-theater`
- `order > 10`（在内建 Chat 与 Trajectory 之后）
- 字典**通过 effect 注册**（插件卸载时自动移除，不泄漏）
- 会话不可用时**抛错而不是渲染空标签页**
- `loadOlder` 如实报告"是否真的加载到了新内容"（用 revision 变化判断，正反两个用例）

## 停顿上限做成控件的理由

设计阶段就定了要可调，但 P2 只是个 prop。做成控件之后有个意外收获：**它成了最好的教学入口**——用户把上限从 2s 调到 ∞，会亲眼看到"原来这段回答中间停了 40 秒"。压缩告知与这个控件配合，把"数据被改动了"这件事变得可探索而非只是被告知。
