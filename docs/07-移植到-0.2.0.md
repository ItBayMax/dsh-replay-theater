# 移植到 dsh 0.2.0

> 基线：`dsh@0.2.0-rc.2`（上游 commit `639ed01`）· 上一基线 `0.1.2-alpha.2`（`0a53fb5`）
> 本文记录一次**纯代码移植**：没有部署到任何实例，没有在真实 dsh 里跑过。
> 结论的证据只有两类——上游源码，与本仓库的 164 个测试。

## 一、为什么必须移植

插件读的是会话历史的"线格式"（wire shape）。0.2.0 把这个形状换了，旧代码不是退化，是直接读不到东西。

移植前 README 顶上挂着一条不兼容警告（commit `dd56911`），本次移植撤掉它。

### 旧形状（0.1.x）

一个历史页里有两种记录，其中"打包"记录**横跨多个逻辑 seq**：

```
{ type: 'chunks', event: { type: 'chunkrow/text-chunks', seq, time, data: { …, dt, texts } } }
```

### 现形状（0.2.0）

```
{ type: 'event', event: { type: 'assistant/message', seq, time, data: { turn, step, stream: [...] } } }
```

`chunkrow/*` 这个事件类型**没了**。在 0.2.0 上 `chunkrow` 在 `packages/` 下的
任何 `.ts`/`.tsx` 里是 **0 命中**。

唯一残留的一处是散文，而且上游忘了更新：

```
packages/client/AGENTS.md:104
… a Definition that consumes Assistant deltas implements both scalar and
`chunkrow/*` branches without expanding members.
```

这份文件是写给实现者（含 AI agent）看的指引。照着它写，会写出一个编译器里
已经不存在的类型分支。**这是移植过程中最值得记下的一个坑**：上游的指引文档
比上游的代码旧。

### 上游是怎么走到这一步的

两条迁移边合起来消掉了旧形状：

1. **v1→v2：把流折进 assistant 事件**。顶层的 `assistant/chunk` 事件被吃掉；
   一次 attempt 落定为一条 `assistant/message`（若没产出面向用户的消息，则是
   `assistant/attempt`），把带时间的流放进 `data.stream`。
2. **v2 起，一条物理行恰好一个事件**。上游自己的 `historyRecordFirstSeq()` 与
   `historyRecordLastSeq()` 现在**都**返回 `record.event.seq`
   （`packages/api/session-controller/src/client/sessions/history-records.ts:24-35`）。

当前会话格式版本是 **4**（`packages/core/session/src/types.ts:89`）。

## 二、节奏数据没有丢，只是挪了一层

这一点我一开始判断错了，先记在这里。

在当前的物理行里找不到 `dt`，我据此说过"节奏数据没了"——**这是错的**。
它被**搬进了** `assistant/message.data.stream[]`，字段名一个没改：
`time0` / `index` / `dt` / `texts` / `args` 原样保留。

而且上游在 0.2.0 里把这件事说得比 0.1.2 更明确：

```ts
// packages/core/session/src/types.ts:341-348
'assistant/message': {
  turn: number
  step: number
  message: AssistantMessage
  /** Exact timed model stream, compacted without joining delta boundaries. */
  stream: AssistantStreamRecord[]
  …
}
```

> *"**Lossless** compact representation of one model-stream attempt"*
> —— `packages/llm/llm/src/assistant-stream.ts:1-2`

所以插件的**前提在 0.2.0 上不但成立，还被上游说得更硬了**：逐 token 间隔
被刻意保留、刻意不合并成一个字符串，而 harness 自己不回放它。

## 三、`stream` 成员的四个变体

`AssistantStreamRecord`（`packages/llm/llm/src/assistant-stream.ts:20-47`）
是四元联合，前三个是打包 run，第四个是累加器从不打包的单个非 delta chunk：

| 变体 | 载荷 | 本插件如何处理 |
|---|---|---|
| `text-chunks` | `texts[]` + `dt[]` | 展开成逐 token 帧 |
| `reasoning-chunks` | `texts[]` + `dt[]` | 同上，渲染进推理块 |
| `tool-call-chunks` | `args[]` + `dt[]` + `id` | 同上，渲染进工具参数块 |
| `chunk` | 单个 `time` + 任意 `chunk` | **渲染成标记**，不展开 |

第四个变体在真实语料里不是边角：从 `snapshots/acp/escalation-approved/session.v3.jsonl`
派生的测试语料共 **23 条记录**，其中 **2 条带 stream**、合计 **16 个成员**，
按变体分布是 `chunk` 12 / `reasoning-chunks` 2 / `tool-call-chunks` 1 / `text-chunks` 1。
**`chunk` 是里面最多的一种。** 把它漏掉，时间线上会凭空少掉一大片。

它没有 `dt`、没有成员序列，展开它是无意义的，所以 `timeline.ts` 用
`SYNTHETIC_CHUNK_MARKER = 'assistant/stream-chunk'` 把它落成一个标记。

## 四、改了什么

```
 src/core/wire.ts        | 250 ++-     结构镜像重写，钉到 639ed01
 src/core/timeline.ts    | 148 ++-     建帧改走 assistantEventData
 src/core/jsonl.ts       | 143 ++-     旧格式"提升"而非分支
 src/client/dsh.ts       |  22 +-      文档修正
 src/index.ts            |   8 +-      导出面调整
 src/client/TheaterStage.tsx |  2 +-   React key 加 seq
```

### `wire.ts`：类型仍然是镜像，不是 import

`@deepseek-ai/dsh-api-session-controller` 没发到 npm，所以继续自持结构镜像，
逐条标注读自哪个 `file:line`，钉在 `639ed01`。

一处真实改动：`streamRecord()` 做**运行时校验**而不是 cast。`data` 上游声明
是 `JsonValue`，一个 `dt` 畸形的成员会产出 NaN 播放位置——那比丢一个成员
难查得多。

`recordLastSeq()` 现在只是 `return record.event.seq`，以前的算术没了。
**它仍然留在导出面上**，因为这个名字承载了一个随版本变化的事实：一次落定的
attempt 只占一个 seq。调用点写成裸 `.event.seq` 就不承载这个信息了。

### `jsonl.ts`：旧日志"提升"，不分支

磁盘上两代格式还都在：

| 代 | 文件名 | assistant delta |
|---|---|---|
| 0 | `session.jsonl[.zstd]` | 一个 run 一个**打包行**，横跨 `seq0 … seq0+n-1` |
| 2+（当前 4） | `session.vN.jsonl[.zstd]` | 一行一事件，打包 run 在 `data.stream` 里 |

没有按 header 版本分支，而是把 generation-0 的打包行**提升**成当前形状——
这正是上游自己的 v0→v1→v2 迁移链在语义上做的事。代价是 `buildTimeline`
永远只见一种记录形状。

提升后仍然 `seq += lifted.span - 1`，否则后面的标量行会撞上这行吃掉的 seq。

一处刻意的不对称：旧格式对畸形 `dt` 成员是**容忍**的（过滤掉），当前格式是
**严格**的（整个成员丢弃）。理由写在代码里——旧文件是没人能重录的历史数据，
一个坏 gap 不该赔上整段 run；而当前格式里出现坏成员，那是个活的 bug。
容忍的代价是 `dt` 变短、后续成员提前，run 还能播，只是被压缩了一点。

### 自审查出来的一个真 bug

`stageAt` 原本按 `(kind, block, turn, step, callId)` 给块分组——**漏了 seq**。

一个被重试的 step 会先落一条 `assistant/attempt`（被放弃的那次），再落一条
`assistant/message`（最终那次），两者**经常共享同一组 turn/step/block**。
结果是：放弃的那次和最终那次的文本会**拼进同一个视觉块**。

这个 bug 在 0.1.x 上不存在，是移植引入的——旧形状里这两次根本不会落在
可比较的坐标上。

修复：`StageBlock` 加 `seq` 字段，`sameBlock` 判据里加 `open.seq === frame.seq`，
`TheaterStage.tsx:40` 的 React key 里也加上。配两个回归测试：

```ts
it('does not merge a retried attempt into the abandoned one', …)  // 期望 2 个块
it('still merges consecutive members of one attempt into a single block', …)  // 期望仍是 1 个
```

第二个测试是必须的：只加第一个的话，一个"每个成员各成一块"的退化实现也能过。

## 五、测试语料

**删除** `tests/fixtures/make-corpus-fixture.mjs`。它是 0.1.2 时期的派生脚本，
读 generation-0 的 `session.jsonl`，产出 `{ type: 'chunks' }` ——一个解析器
已经不接受的形状。留着它的风险很具体：谁跑一次就会把夹具"重新生成"成坏的，
而且它文件头里那条"语料中最富的快照总共只有 3 个 text-delta"的判断，实测
也已经不成立（最长 run 有 2047 个成员）。

新增 `scripts/make-corpus-fixture.mjs`，从上游快照
`snapshots/acp/escalation-approved/session.v3.jsonl` 派生
`tests/fixtures/corpus-escalation-approved.json`，并补回被归一化剥掉的 seq/time。

用真实语料而不是手写夹具的理由，在 `chunk` 变体占 12/16 这个数字上体现得最清楚：
手写夹具不会想到去造那么多 `chunk`。

### 全量语料扫了一遍，结论和 0.1.2 时期相反

移植时顺手把上游全部 v3 快照扫了一遍（`639ed01`），结果推翻了 README 和
`synthetic.ts` 里沿用至今的一条断言。旧断言是：

> 语料无法承载节奏断言：归一化剥掉了 `seq`/`time`，而全部 **118** 个快照会话里
> 最长的"连续同块 delta"只有 **2** 个成员。

实测：

| 项 | 旧断言 | `639ed01` 实测 |
|---|---|---|
| v3 会话数 | 118 | **173**（168 个带 stream） |
| 打包 run 总数 | — | **526** |
| 最长单段 run | 2 个成员 | **2047** 个成员（`web/present-svg` 的一段 tool-call） |
| run 内 `time0`/`dt` | 被剥掉 | **526/526 全部保留**，400 个不同的 `time0` epoch 毫秒值 |
| 行级 `seq`/`time` | 被剥掉 | 确实被剥掉（4343 行里 0 行保留） |

所以**形状覆盖**从"几乎没有"变成了"很充分"；但**真实节奏**依然拿不到：
526 段 run 里 373 段的 `dt` 全为零，整个语料里最大的一个间隔只有 **156 ms**。
这些会话是对着快速或打桩模型录的，没有"模型停下来想几十秒"那种节奏。
计时测试因此仍然走合成夹具。

这条扫描直接带出一个测试缺口：所有既有夹具都只有几个成员，逐成员累加
**从来没在真实规模上跑过**。补了一个：

```ts
it('expands a run as long as the longest one upstream actually records', …)
// 2047 个成员：帧数、总时长、seq 唯一性、累加是否走到最后一个成员
```

2047 这个数不是随手取的，就是上游语料里的实际上限。

## 七、清单变更

```json
"version": "0.2.0",
"dsh": { "manifestVersion": 1 },
"engines": { "dsh": "^0.2.0" }
```

`engines.dsh` 是新加的。上游在小版本之间会整包删除客户端代码，插件需要在
安装时就撞墙，而不是在运行时读到空历史后静默播一个空舞台。
