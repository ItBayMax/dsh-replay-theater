## 真实环境抓到三个 bug（单元测试全绿也测不出）

### 1 & 2：JSONL 存储格式（用生产会话发现）

用一个 5776 事件的真实生产会话（3.86MB / 2775 打包行 / 57401 token / 54626 个 dt）跑 CLI，发现：

- **打包行坐标是 `seq0`/`time0`，不是 `seq`/`time`**。上游 `ChunkRow`（存储形态）与 `ChunkRowEvent`（wire 形态）字段名不同，我只处理了 `type` 的差异。后果：2455 个打包行的时间戳未识别 → 误报 `synthetic times: true`。
- **首行 `SessionHeader` 被当成事件**占用 seq 0 → 后续 seq 全部错位（实测出现两个 seq=1）。

修复后同一份会话：`synthetic times` true→false；seq 严格递增；总时长 2585801ms（合成虚高）→ **1357454ms**（真实 22.6 分钟）；压缩处数 1033（误判）→ **204**。首 token 的 105ms 真实延迟如实呈现。

### 3：分发形态（装进真实 dsh 才发现）

第一次安装直接崩溃：

```
ENOENT: stat '.../dsh-replay-theater/lib/client.js'
```

dsh 的 `ClientModuleRegistry` 要求**单文件自注册 bundle**，而 `tsc` 逐文件编译产出的是 `lib/client/index.js`。我在 P0 抄了 ui-schedule 的 `exports` 声明，却没抄它的构建方式（上游用 tsdown preset）。

修复：`scripts/build-client.mjs` 用 esbuild 复刻上游 `clientBundle` preset 的产物格式（`packages/client/tsdown.client.ts`）：

```js
window.__ModuleLoader__.load({ id: "dsh-replay-theater", factory: (require) => {
var module = { exports: {} }; var exports = module.exports;
…CJS bundle，externals 走注入的 require…
return module.exports; } });
```

三个要点：`format: 'cjs'` + `platform: 'browser'`；externals 严格等于宿主 seed 表 `PLATFORM_MODULES`（多了会 require 不到而崩，少了会内联重复实例）；CSS module 经 lightningcss 编译成 hash class map + 运行时注入 `<style data-plugin-css>`。

## 一条重要的产品发现：真实 dt 中位数是 0ms

54626 个真实 gap 里**中位数为 0**（provider chunk 常在同一毫秒到达，日志时钟是毫秒精度），最大 1033ms，负值 0 个。

意味着逐字回放会让整段文字瞬间出现。因此新增 `minGapMs`：给零间隔一个下限以恢复可见打字效果，且**不虚构结构**——真正长的停顿保持原样。先 floor 再 ceiling，floor 不会把被压缩的间隔重新拉长。

（负 dt 在这个样本里是 0 个——我们的钳制是按上游文档的防御性设计，实测未触发，保留是对的。）

## 一次误报的自我更正

浏览器自动化点"下一帧"时读数不动，我一度以为 `step` 有 bug。程序化 `.click()` 后正常推进（`1/16`→`2/16`）——是**自动化坐标点击没命中按钮**，不是插件问题。记录在此以免后来者误判。

## 未在此环境验证的部分

- **生产实例升级**：那台服务器的生产 dsh 是 `0.1.1-rc.2` 的定制 fork（含 3 个自研 kpptx 包，`workspace:^` 依赖），且 GitHub 不可达、仓库无 0.1.2 commit → 无正确升级路径。本次验证用的是**旁边独立安装的纯净实例**，未触碰生产。
- **长 token 流的视觉效果**：测试会话只有 16 帧（无 API key，模型请求失败）。真实长回复的打字效果需带 key 的会话，或用离线模式载入生产日志。
