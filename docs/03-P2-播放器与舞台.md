## 设计：为什么状态机与 React 分离

`core/player.ts` 不 import React、不碰计时器、不调 `requestAnimationFrame`。它只做一件事：**给定当前状态与一个墙钟读数，算出新状态**。

```ts
tick(player, nowMs)  → Player      // 时钟推进
seek(player, ms, nowMs) → Player   // 绝对跳转
step(player, delta) → Player       // 整帧步进（会暂停）
```

好处直接体现在测试里——**29 个播放规则测试全部不需要计时器、不需要 DOM、不需要 fake timers**，只是喂不同的 `nowMs`：

```ts
it('scales elapsed time by the speed', () => {
  const started = setSpeed(play(createPlayer(timeline), 1_000), 2, 1_000)
  expect(tick(started, 1_050).state.positionMs).toBe(100)   // 50ms 墙钟 × 2 倍速
})
```

调度的职责在 `usePlayback.ts`（唯一 import React 的地方），它只管三件核心做不到的事：订阅 `session.eventSource`、用 rAF 驱动 `tick`、暴露命令。

## 五个值得记录的行为决策

### 1. 时钟倒退绝不倒放

```ts
const elapsed = Math.max(0, nowMs - previous)
```

与建帧阶段钳制负 `dt` 是同一条原则的两处落实：**时间可能不单调，播放头必须单调**。

### 2. 播完即停，不空烧动画帧

`tick` 到达末尾时把 `playing` 置 false 并**删掉时钟锚点**——否则 rAF 循环会在播放结束后继续跑。

### 3. 在末尾按播放 = 重播

`play()` 检测到播放头已在末尾就从 0 开始。否则播放按钮在播完后看起来是坏的。

### 4. `retarget`：窗口增长不丢播放头

这是 P2 最关键的一个决策。用户点"加载更早"或会话正在流式输出时，时间线会变长。天真实现会重建播放器 → 播放头弹回开头 → **"加载更早"功能实际不可用**。

```ts
export function retarget(player: Player, timeline: Timeline): Player {
  const positionMs = Math.min(player.state.positionMs, timeline.totalMs)
  return { timeline, state: { ...player.state, positionMs, frameIndex: frameIndexAt(timeline, positionMs) } }
}
```

有组件级测试守着："窗口增长后播放头不动，追加的帧尚未显示"。

### 5. 单步会暂停

单步时若仍在播放，rAF 循环会立刻把播放头冲走。所以 `step()` 内部调 `pause()`。

## 舞台的两个取舍

**工具调用只显示占位**：`tool-args` 段落用等宽字体显示累积的 JSON 片段 + 工具名，**不复刻 `ui-tool` 的完整卡片体系**。理由写在设计阶段：那会牵入大量依赖，而卡片本身不是"节奏回放"的价值所在。

**压缩必须告知**：播放条在 `compressedGaps > 0` 时显示"长静默已压缩 N 毫秒"。这是有意的诚实——回放改动了数据的时间，用户有权知道。有正反两个测试守着（压缩时显示、`maxGapMs: Infinity` 时不显示）。

## 组件测试覆盖的 19 个行为

- **渲染**（3）：有内容时渲染舞台+播放条、初始只显示第一个 token、空窗口自陈其空
- **交互**（5）：单步前进/后退改变文本、拖拽跳转、播放按钮 aria-label 切换、restart 回到首帧
- **契约**（3）：倍速选项与 `core` 的 `SPEEDS` 一致、空时间线禁用播放条、marker 渲染
- **诚实性**（2）：压缩时显示告知、不压缩时不显示
- **分页**（3）：`hasMore` 才显示按钮、点击调用注入的分页函数、失败不卡死按钮
- **端到端**（1）：**真实 rAF 驱动**播放到结束（jsdom 真定时器，非 fake timers）
- **工具函数**（2）：`formatPosition` 的分/秒/十分之秒格式与负值钳制

其中"真实 rAF 播放到结束"这条最有价值——它证明状态机、React 绑定、rAF 循环、舞台累积四者串起来真的能动，而不只是各自单元正确。
